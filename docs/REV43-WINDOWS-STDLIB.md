# Craft 0.1.43 — Windows Standard Library

Rev.43 adds six typed `std` modules. They are built into `craft.exe`; a Craft project does not install or import a package to use them. The supported release target is Windows amd64. `std.encoding`, `std.crypto`, `std.url`, and `std.regex` use OS-independent Go libraries; `std.process` and `std.os` are exercised on Windows.

| Module | Public functions | Results and behavior |
| --- | --- | --- |
| `std.encoding` | `base64Encode(Bytes)`, `base64Decode(String)`, `hexEncode(Bytes)`, `hexDecode(String)` | Standard padded Base64 and lowercase hex. Decoders reject malformed input and return `Bytes`. |
| `std.crypto` | `sha256(Bytes)`, `hmacSha256(Bytes, Bytes)`, `secureRandom(Int)`, `uuid()`, `secureEqual(Bytes, Bytes)` | SHA-256/HMAC digests are raw `Bytes`; `uuid` creates a random version 4 UUID; `secureEqual` compares MAC-like byte strings. SHA-256 alone is not a password storage API. |
| `std.url` | `parse(String)`, `encode(String)`, `decode(String)`, `query(String)` | `encode`/`decode` use query-component rules (`+` means space on decode). `query` returns `Map<String, String[]>` and retains repeated values in order. `parse` returns `UrlParts { scheme, host, path, rawQuery, fragment }` and performs no network request. |
| `std.process` | `run(String, String[], Int, Int)`, `start(String, String[], Int)`, `wait(Process, Int)`, `kill(Process)`, `exitCode(Process)` | `run` and `wait` return `ProcessResult { exitCode: Int, stdout: Bytes, stderr: Bytes }`. The last two `run` arguments are timeout in milliseconds and maximum combined output bytes. `start` takes maximum combined output bytes; `wait` takes timeout in milliseconds. `exitCode` returns `Int?`. A nonzero child exit is a result, not a launch exception. |
| `std.regex` | `match(String, String)`, `find(String, String)`, `replace(String, String, String)`, `split(String, String)` | Go RE2 patterns. `find` returns `RegexMatch? { text, start, end }`, with Unicode code-point offsets. Replacement supports RE2 capture expansion. |
| `std.os` | `version()`, `architecture()`, `processId()`, `open(String)` | `version` reports the Windows kernel version and build, `architecture` is the running Craft process architecture, and `open` asks Windows to open a file, folder, or `http`/`https`/`mailto` URL with its default handler. |

`std.process` executes a program with a separate argument array; it does not assemble a command line for `cmd.exe`. Batch scripts (`.bat`, `.cmd`) are rejected. Child windows are hidden. Each started process belongs to the Craft function call that created it. If the function exits before its child finishes, Craft kills and reaps the child. Call `wait` inside that function to obtain its output and exit code. `kill` stops a child; call `wait` afterward to collect the result. `run` and `wait` accept a timeout from 1 to 300000 ms. Combined captured stdout and stderr is limited to 16 MiB, and the caller may choose a smaller limit. Output is drained even after the limit is reached; the call then raises `ProcessLimitError`.

Encoding decoders and `Bytes` outputs are limited to 16 MiB. `secureRandom` accepts 0 to 1048576 bytes. URL input is limited to 1 MiB; regex patterns to 4096 bytes and regex input/output to 16 MiB, with a 100000-result cap for replace/split. Invalid encoding, URL, pattern, launch, timeout, or output-limit operations raise specific runtime errors. Avoid logging secrets passed to `hmacSha256` or data returned by child processes.

See [`examples/rev43-stdlib`](../examples/rev43-stdlib) for a Craft-only example. From that directory run `craft check`, `craft test`, `craft fmt --check`, and `craft run`. The example's `main` runs `hostname.exe`; `std.os.open` is intentionally not called because it launches an external handler.
