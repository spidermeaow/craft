# Craft Phase 1 Rev.36 (0.1.36) — VirtualGrid cell editor and input focus

วันที่: 9 ตุลาคม 2026  
สถานะ: **ผู้ใช้ทดสอบ UI Showcase แล้ว ยืนยันว่าทำงานเร็ว ภาพสวย และแก้ข้อมูลในเซลล์ได้จริง**  
ฐาน: ผู้ใช้ยืนยันว่า Rev.35 แก้อาการภาพซ้อนและความช้าในหน้า Excel แล้ว แต่การแก้ค่าเซลล์ยังไม่ผ่าน

## ปัญหาและขอบเขต

VirtualGrid ใน Rev.34 เลือกและเดินเซลล์ได้ แต่รับเฉพาะ Text nodes จึงวาง TextInput ตรงเซลล์ไม่ได้. Showcase เคยสร้าง native TextInput ทุกเซลล์จน scroll ช้า แล้วเปลี่ยนเป็น Canvas สำหรับเซลล์ส่วนใหญ่และ TextInput ตัวเดียวสำหรับเซลล์ที่เลือก. วิธีหลังลดภาระได้ แต่ต้องสลับชนิด node ใน layout ที่แอปประกอบเอง และยังไม่มีผลตรวจรับว่าคลิกแล้วแก้ค่าได้จริง.

Rev.36 เพิ่ม primitive ทั่วไปสำหรับตารางข้อมูล ไม่ใส่ความรู้เรื่องสูตร, workbook หรือไฟล์ Excel ลงใน Engine. แอปยังเป็นเจ้าของข้อมูล, ค่าเดิม/ค่าใหม่, การยืนยัน/ยกเลิก และการนำค่าไปใช้.

## สิ่งที่ implement

1. เพิ่ม `std.ui.gridEditor(grid, row, column, editor)` และ `gui.gridEditor(...)` โดย `grid` เป็น VirtualGrid, `editor` เป็น TextInput ที่เปิดใช้งาน และ row/column เป็นดัชนีฐานศูนย์. Runtime ตรวจชนิด, พิกัด, node ID และข้อจำกัด tree. Editor เป็น child หนึ่งตัวท้าย grid; ข้อมูลเซลล์ที่โหลดเข้ามายังเป็น Text nodes ตามเดิม.
2. Layout วาง editor ตามพิกัดเซลล์ที่ระบุด้วย scroll offset สองแกนของ VirtualGrid. Native EDIT ใช้เส้นทาง clipping/repaint เดียวกับ TextInput ปกติ. เมื่อ update ตารางเพื่อย้าย editor ให้คง ID เดิมและ HWND เดิม; แอปเรียก `setText` เพื่อเปลี่ยนค่าใน editor ตามเซลล์ใหม่.
3. การนับเซลล์ที่โหลด, การขอช่วงข้อมูล และเส้นกรอบ grid ของ Direct2D/GDI ไม่นับ editor เป็น data cell. การเลื่อนยังย้ายทั้งเซลล์และ editor ไปด้วยกัน.
4. แก้ `focusNode` ให้ตรวจ native Windows focus เมื่อขอ focus TextInput ID เดิม. ถ้า Engine จำ ID ไว้แต่ Windows focus ไปที่ control อื่นแล้ว ให้เรียก `SetFocus` อีกครั้ง.
5. ปรับ UI Showcase หน้า Excel ให้ใช้ VirtualGrid 18×10 กับ TextInput ตัวเดียวที่วางบนเซลล์ที่เลือก. `GridCellPressed` และ `GridSelectionMoved` เลือกเซลล์; `TextChanged` อัปเดต mock data; Enter ยืนยัน, Escape คืนค่าเดิม, Tab ไปเซลล์ถัดไป. Value bar และ Apply ยังใช้งานได้.
6. หลังผู้ใช้รายงานว่าหน้าตาตารางแย่ลง ปรับ Showcase ให้กลับมาใช้หัวแถวเลขกว้าง 48 px และหัวคอลัมน์แบบเดิม และเพิ่ม padding ข้อความของ Text cell ใน VirtualGrid ทั้ง Direct2D/GDI เพื่อไม่ให้ข้อความชิดเส้นกรอบ. ข้อความใน editor วางตำแหน่งใกล้กับข้อความเมื่อไม่ได้แก้.
7. ให้ `scrollFocusIntoView` คำนวณ viewport ของ VirtualGrid เมื่อ focus ย้ายไปยัง editor ที่อยู่นอกส่วนที่มองเห็น เพื่อให้ editor กับตำแหน่งรับ input ยังสัมพันธ์กับเซลล์หลังเลื่อน.
8. แก้การอ่านค่าจาก native EDIT ใน Runtime ให้ใช้ `WM_GETTEXTLENGTH` และ `WM_GETTEXT`. ก่อนแก้ editor แสดงข้อความที่พิมพ์ แต่ `TextChanged`/`TextSubmitted` ส่งค่าว่าง ทำให้ value bar ไม่ตามและกด Enter แล้วเซลล์ว่าง. ปรับการ focus VirtualGrid ให้เลื่อนตามกรอบเซลล์ที่เลือก แทนกรอบตารางทั้งก้อน ซึ่งเคยทำให้หน้าเลื่อนกระโดดเมื่อคลิกเซลล์.

## ผลทดสอบ UI จริงล่าสุด

- ใช้ `craft check` กับ Showcase ได้ และเปิด Showcase ด้วย `craft run` จาก portable binary ที่ build ใหม่.
- คลิก B2 แล้วแก้ค่า กด Enter จากนั้นย้ายไป A10: ค่า B2 ยังอยู่. คลิก A10 แล้วพิมพ์ กด Escape: ค่าเดิมกลับมา. ตั้งค่า A10 แล้วกด Tab: ค่า A10 คงอยู่และเลือก B10. คลิกเซลล์ไม่ทำให้หน้าเลื่อนกระโดดแล้ว.
- ใช้ value bar เปลี่ยน B10 แล้วกด Apply: ข้อความใหม่ปรากฏในเซลล์ B10.
- ก่อนเปลี่ยน antialiasing ภาพตัวอักษรในตารางและข้อความบางส่วนแหว่ง/ไม่สม่ำเสมอทั้ง Direct2D และ GDI. หลังเปลี่ยน ผู้ใช้รายงานว่าภาพสวยและทำงานเร็ว; ยังไม่ได้ตรวจ DPI หลายค่า, IME หรือการเลื่อนเร็วเชิงลึก.

## ปัญหาล่าสุดที่ต้องแก้ก่อนปิด Rev.36: ตัวอักษรแหว่ง

**อาการก่อนแก้:** ข้อความในเซลล์ Excel และข้อความบางจุดนอกตารางมีส่วนของตัวอักษรหายหรือแสดงไม่สม่ำเสมอ ตั้งแต่ภาพแรกและหลังเลื่อนหน้า. ข้อมูลใน accessibility tree ยังเป็นข้อความครบ จึงเป็นปัญหาการแสดงผล ไม่ใช่การเก็บค่าของเซลล์. พบอาการคล้ายกันเมื่อบังคับ `CRAFT_UI_RENDERER=gdi` และเมื่อใช้ Direct2D ตามค่าเริ่มต้น.

**สาเหตุ:** ยังไม่ยืนยัน. การพบในสอง renderer ทำให้ต้องตรวจส่วนที่ใช้ร่วมกันก่อน ได้แก่ layout ของ Text node, clipping, การคำนวณพื้นที่ที่ต้องวาดใหม่ และการซ้อนทับ native TextInput; ยังไม่ควรระบุว่า Direct2D หรือ GDI เป็นสาเหตุ.

**งานแก้และเกณฑ์ผ่าน:**

1. ทำตัวอย่าง Text และ VirtualGrid ขนาดเล็กที่เกิดอาการซ้ำได้ แล้วเทียบตำแหน่ง/ขนาด node กับพื้นที่ที่ถูก clip และสั่ง repaint ก่อนแก้ Showcase เพิ่ม.
2. ตรวจการวาดเต็มหน้ากับการวาดเฉพาะ dirty region, การเลื่อน/resize และตำแหน่ง native EDIT เพื่อแยกว่าข้อความถูกวาดไม่ครบหรือถูกวาดทับภายหลัง.
3. แก้ที่ Runtime หรือ layout ตามหลักฐาน และตรวจซ้ำทั้ง Direct2D/GDI: ตัวอักษรทุกแถวต้องครบในภาพแรก หลังเลื่อน และหลังแก้ค่าเซลล์ โดยยังรักษาความถูกต้องของ Enter, Escape, Tab และ Apply.

**การปรับปรุงรอบล่าสุด:** เปลี่ยน text antialiasing ของ Direct2D เป็น grayscale และเปลี่ยน GDI font quality จาก ClearType เป็น antialiased สำหรับข้อความทั่วไป ข้อความปรับสไตล์ และ Canvas. ผู้ใช้ทดสอบ UI Showcase หลังการเปลี่ยนนี้แล้วรายงานว่าเร็ว ภาพสวย และแก้ข้อมูลได้จริง. ผลดังกล่าวยืนยันพฤติกรรมของชุดทดสอบที่ใช้งาน แต่ยังไม่พิสูจน์เชิงแยกตัวแปรว่า ClearType เป็นสาเหตุเดิมทั้งหมด.

**ผลตรวจรับจากผู้ใช้:** หน้า Excel ของ UI Showcase ผ่านในด้านความเร็ว ความสวยงามของภาพ และการแก้ข้อมูลในเซลล์ตามรายงานล่าสุด. ยังไม่มีผลยืนยันแยกสำหรับ DPI 100%/125%, GDI fallback, IME ภาษาไทย และกรณีเลื่อนเร็วหรือ resize ทุกแบบ; หากพบอาการซ้ำให้ใช้ขั้นตอนตรวจ clipping/repaint ข้างต้น.

## สัญญา API และข้อจำกัด

- `gridEditor` จัดการตำแหน่งและ native input เท่านั้น; ไม่เก็บข้อมูลของตาราง ไม่คำนวณสูตร และไม่ตัดสินว่าจะบันทึกหรือยกเลิก. Event ของ editor ใช้ `nodeId` ของ TextInput ที่แอปส่งเข้ามา.
- แอปควรใช้ ID เดิมสำหรับ editor ระหว่างเปลี่ยนเซลล์ และเรียก `setText(window, editorId, value)` หลัง `update` เมื่อค่าเป้าหมายเปลี่ยน. การแก้ใน Showcase ปัจจุบันสะท้อนลง mock data เมื่อ `TextChanged`; Escape คืนค่าก่อนเริ่มแก้เซลล์นั้น.
- Rev.36 ยังไม่มี range selection, clipboard ช่วงข้อมูล, frozen panes, accessibility แบบ virtualized หรือ dirty-cell rendering. ไม่มีการประกาศว่าความสามารถ Excel Final ผ่านแล้ว.
- UI Runtime ยังคงรองรับ Windows เท่านั้น. การวัด latency/frame time แบบเชิงปริมาณและการตรวจ DPI/renderer หลายรูปแบบยังต้องอาศัยผลทดสอบจริง.

## เกณฑ์ตรวจรับโดยผู้ใช้

1. เปิดหน้า Excel คลิก B2 พิมพ์ค่าใหม่ คลิก A10 แล้วกลับ B2: ค่าใหม่ต้องอยู่ใน B2 และ editor ต้องวางตรงเซลล์ที่เลือก.
2. แก้ค่าแล้วกด Escape: กลับเป็นค่าก่อนเริ่มแก้; แก้แล้วกด Enter: ค่าใหม่คงอยู่. กด Tab: editor ไปเซลล์ถัดไปและค่าเดิมไม่หาย.
3. ใช้ value bar แก้เซลล์ที่เลือกด้วย Enter และ Apply; editor และตารางต้องแสดงค่าเดียวกัน.
4. เลื่อนแนวตั้ง/แนวนอน, resize และสลับหน้าแล้วกลับมา: editor ต้องไม่ลอยผิดพิกัด, ไม่ทิ้งภาพค้าง, ค่าไม่ข้ามเซลล์ และความเร็วไม่ถอยกลับแบบ 180 native TextInputs.
5. ตรวจที่ DPI 100% และ 125% รวมทั้ง Direct2D และ GDI fallback ถ้าทำได้; บันทึกพฤติกรรม focus, caret และ IME ภาษาไทย.

ผู้ใช้เป็นผู้ทดสอบ UI จริงตามแนวทางโครงการ. การ build portable binary และการล็อก package ไม่ถือเป็นผลผ่านเกณฑ์. หากข้อ 1–3 ยังไม่ผ่าน ให้เก็บ event/focus/ค่าใน Runtime และ Showcase แยกกันก่อนขยายฟีเจอร์ grid ต่อ.
